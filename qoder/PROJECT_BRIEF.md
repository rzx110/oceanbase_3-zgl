# 研迹 · Research Desk — Qoder 开发任务书

本文件是项目需求与验收计划，不是已实现功能的声明。主要应用代码、调试及发布工作应在真实 Qoder 会话中完成，并保留可核对的开发记录。

## 项目定位

为学习、科研和工作中经常中断、需要重新整理背景的项目提供一个本地优先的进度记忆台。把资料摘录、任务进展、决策、待解决问题和偏好保存为可追溯的上下文。重新打开后，能搜索以前的记录并生成带出处的继续工作清单。

项目名称：研迹 / Research Desk。界面以简体中文为主，适合用于竞赛演示，但不能声称存在未经验证的用户数量或效率提升数据。

## 核心工作流

1. 建立独立项目，例如“论文复现”和“每周业务复盘”。
2. 向指定项目添加资料摘录、进度、决策、阻塞问题、偏好；记录标题、正文、类别和可选出处 URL。
3. 通过真实 PowerContext Source、Runtime ingestion 和 scoped Memory 保存、索引记录。无模型 API Key 也能运行，可使用透明的确定性 pipeline。
4. 在当前项目检索历史上下文，展示可回查的精确 citation；点击后通过 Memory API 读取原始记录，并展示 Source 来源。
5. 重启应用后保存的记录仍能检索；不同项目不能串数据。
6. “继续工作”视图按明确规则整理已完成进度、未解决阻塞、最新决策和下一步，显示每项依据。不能伪称使用了在线大模型。
7. 演示数据显式一键导入且幂等，提供空状态、加载、错误反馈和移动端布局。

## 实现建议（由 Qoder 判断具体实现）

- Python 3.12 + PowerContext SQLite Runtime；本地 HTTP 后端搭配轻量现代网页前端。
- PowerContext 的依赖应固定到可获取的版本或 commit。可用官方冻结产品版本 `9db1753434162c0aa7c9f1189a1722e617880a52`，并写明来源及 Apache-2.0 许可。
- 现有 API 参考可只读查看 `D:/oceanbase-powercontext/src/powercontext/` 和对应 tests、docs，但不得修改那个目录或其分支。
- 如需参考现有测试，`tests/test_pdf_pages.py` 中真实 Runtime、确定性 pipeline、scoped Memory 和 citation 回查示例可帮助理解接口；本项目不需要实现 PDF 题目。
- 项目主路径为 `D:/oceanbase-qoder/qoder/`。不要修改其他赛道目录，也不要自行提交竞赛评分。
- 本地服务默认监听 `127.0.0.1`；公开网站仅展示虚构示例及明确标注的实际验证结果。

## 视觉要求

安静、清晰、有辨识度的研究工作台：暖白背景、深青色、少量暖橙强调；清晰的项目侧栏、今日继续工作区、上下文搜索和引用详情。避免满屏渐变卡片或把 README 直接当网页。桌面与手机都应可用。公开 Sites 页面需要有清晰价值说明、真实截图、三步使用说明、技术闭环和源码/本地运行入口。

## 必须执行的验收

- 在临时数据库导入两组演示项目，核对 Source 和 Memory 的真实写入。
- 检索与 citation 回查返回相同项目、相同记录，出处完整；跨项目隔离。
- 重复导入幂等；停止并重新启动后仍能查回记录。
- 新增资料、更新任务状态、重新检索及“继续工作”清单内容正确。
- 查询不存在的内容、空查询、空项目、错误参数和后端异常时有明确行为，不能伪造成功。
- 运行可执行的端到端验证脚本并保留实际输出。验证应能由评审在干净环境中复现。
- 在浏览器实际操作界面并留存真实截图；不能拿设计稿代替运行截图。
- 通过 Qoder Sites 发布后，验证无需登录即可访问，源码链接和说明可用。
